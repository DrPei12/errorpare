## 1. 产品定位

### 1.1 目标用户

| 用户类型 | 描述 | 占比预估 |
|---------|------|---------|
| **A 类用户** | 轻量使用者，零配置，仅需基础压缩 | 70% |
| **B 类用户** | 深度使用者，愿意配置 LLM，需要根因分析 | 30% |

### 1.2 核心价值

- **A 类模式（轻量压缩）** - 开箱即用，60-90% 压缩率，毫秒级延迟
- **B 类模式（深度分析）** - 用户自选 LLM，JSON 格式输出根因 + 建议，1-5 秒延迟

## 2. 技术架构

### 2.1 双模式设计

```
┌─────────────────────────────────────────────────────────────────┐
│                        ErrorPare CLI                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                  │
│   ┌─────────────────────┐         ┌─────────────────────┐       │
│   │   A 类模式 (默认)    │         │   B 类模式 (可选)    │       │
│   │                     │         │                     │       │
│   │ • 零配置            │         │ • 需配置 LLM API    │       │
│   │ • 本地去重压缩       │         │ • 本地规则引擎      │       │
│   │ • 60-90% 压缩率      │         │ • LLM 根因分析       │       │
│   │ • 毫秒级延迟         │         │ • JSON 结构化输出    │       │
│   └─────────────────────┘         └─────────────────────┘       │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 2.2 配置系统（仿照 OpenClaw）

**配置方式：**
1. **交互式向导** - `errorpare init` 引导配置
2. **配置文件** - `~/.errorpare/config.json`
3. **环境变量** - `ERRORPARE_LLM_MODEL`, `ERRORPARE_LLM_API_KEY`

**配置内容：**
```json
{
  "mode": "basic",  // "basic" | "analyze"
  "llm": {
    "provider": "bailian",
    "model": "kimi-k2.5",
    "apiKey": "sk-xxx",
    "baseUrl": "https://api.moonshot.ai/v1"
  }
}
```

## 5. 用户故事

### A 类用户故事
```
作为一个 独立开发者
我希望 零配置使用 errorpare
以便 快速压缩报错，节省 Token
验收标准:
  - npm install -g errorpare 后即可使用
  - errorpare run "npm run build" 输出压缩报错
  - 压缩率 60-90%
```

### B 类用户故事
```
作为一个 专业开发者
我希望 配置自选 LLM 进行深度分析
以便 获得根因分析和修复建议
验收标准:
  - errorpare init 引导配置 LLM
  - errorpare run "npm run build" --analyze 输出 JSON
  - JSON 包含 rootCause 和 suggestion 字段
```

## 6. 风险与缓解

| 风险 | 影响 | 缓解措施 |
